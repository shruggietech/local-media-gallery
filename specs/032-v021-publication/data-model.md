# Data model: v0.2.1 publication and verification

- **Elected qualification**: run ID, event/workflow/ref, source revision/hash/file count, terminal checks and nine canonical receipts; Windows supporting transfers retain immutable IDs/digests/sizes and one accepted clock.
- **Accepted candidate**: candidate ID, product version/predecessor, source, seven product/source descriptors and retained documentation identity. It transitions through staged, published and canonical observed states under the existing publisher.
- **Remote publication**: actual release/tag IDs, asset IDs/names/sizes/hashes, canonical metadata hash, public latest selection and execution journal. Recovery refers to the same accepted candidate and prior execution run.
- **Documentation proof**: renderer source, retained inventories/review, candidate/publication gate records and exact exported files. Actual Pages/live readback is a separate observation.
- **Recipient proof**: platform, selected canonical candidate ID/hash and version, exact artifact name/bytes/hash, preparation/reuse/relocation/native Refresh evidence and original retained operands. Its parent diagnostic CI candidate is not publication identity.
- **Closeout**: explicit owner authority, chronology, distinct preparation/qualification/combined timing, preserved failures, issue/Project state and final verification report.

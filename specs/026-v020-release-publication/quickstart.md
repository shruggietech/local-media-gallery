# Validation and future publication guide

## Preparation validation

1. Use the S026 feature selector and branch; install only already elected locked prerequisites through the verified headless launcher.
2. Run the fixed historical preservation and current documentation receipt regressions, npm run check, npm test and npm run check:docs. Current prose edits must fail stale-receipt validation until the reviewed current recapture is complete.
3. Build the actual site, run check:site and test:site with headless Chromium, and exercise the existing actual candidate-documentation and controlled publication/browser gates.
4. Push/open the official PR, require all nine applicable final-head qualification scopes and independently read back original artifact hashes, exact source/revision, six literal products, native lifecycle/offline evidence and website/docs output.
5. Resolve actual findings under the two-round cap and stop for owner final review and merge. Native GUI/input/installers run only on isolated hosted desktops.

## Future publication after owner merge and authorization

1. Select the successful final merged-main Qualification run and independently verify its retained assets/receipts. Earlier branch or S025 runs are not the elected final run.
2. Invoke the existing release.yml workflow on current main with the exact inputs in [publication-handoff.md](contracts/publication-handoff.md). Use version0.2.0 and predecessor0.1.0, leaving resume empty unless attributable recovery is required.
3. Observe publication and independently verify public assets/hashes/URLs, canonical release metadata, both documentation gates, Pages/latest/download selection and real published recipient acquisition. Reuse accepted bytes without rebuilding.
4. Only after observed success close release tracking/milestone and perform housekeeping. No attended owner desktop gate is introduced.

This is a future procedure, not a report that v0.2.0 has been published.

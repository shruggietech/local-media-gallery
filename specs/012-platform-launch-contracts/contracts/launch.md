# S012 Launch Contract

The public executable remains local-media-gallery (platform suffix/bundle rules apply). Shorthand [DIRECTORY] is open; -- protects literal reserved/dash-leading paths. Named operations: open [DIRECTORY], resolve [DIRECTORY], capabilities, prepare [DIRECTORY], install, --help, --version. --json requests exactly one versioned UTF-8 stdout result; human diagnostics use stderr. --wait/--detach apply only to open and conflict with each other; wait is default. Finite operations reject UI lifecycle flags.

Full default root is null (selection); Lite default root is the external containing gallery. Explicit paths resolve using invoking native cwd semantics before child spawn. macOS exact .app/Contents/MacOS layout uses the app parent. Linux APPIMAGE original absolute regular file wins in package context; invalid/missing origin with APPDIR rejects placement. Plain executable parent applies otherwise. Resolve previews root intent and does not certify discovery, access or missing-media outcomes.

Shared result status: accepted/success/running/partial/cancelled/unavailable/failed. Exit0 accepted/success,1 failed,2 invalid request,3 partial,4 cancelled,5 unavailable capability,6 startup timeout. UI wait success means event-loop lifetime ended normally; detach accepted means matching native startup bridge/root request acknowledgement, not completed enumeration. Startup deadline30s covers accept/read, result max16KiB, match nonce/operation/PID. Timeout reports unknown child lifetime, no termination assertion. Private child uses null standard streams and hidden noninteractive creation; no shell.

Public main-window application_info returns the same capabilities/identity result as the finite CLI. Public operation_result(operationId) is main-window-only and maps the current discovery record into the same result form. Stale IDs reject. Existing snapshot display roots gain exact native-path attribution, counts remain strings. Prepare/install currently return unavailable/capability_unavailable without writes. Provider implementation belongs to their own slices. Both editions share current settings/history resolver and browsing capabilities; recipient state is local to the recipient.

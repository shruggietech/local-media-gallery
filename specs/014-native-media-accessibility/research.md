# S014 Research Decisions

## 2026-10-27: Native automation

Decision: reuse the installed embedded native WebDriver, which supports WebView2, WebKitGTK and WKWebView. External tauri-driver's macOS limitation does not apply to this provider. Keep bounded direct W3C requests and native snapshots; its JavaScript clicks/keys/computed labels are not native input/AX proof. Queue AppKit NSEvent pairs in-process on macOS, use native X11 input under private Xvfb/DBus on Linux, and retain foreground-confirmed Windows input. Assert trusted event/default behavior on each actual runtime.

Alternatives: new eval/result protocol and external Chromium rejected as redundant or the wrong runtime. Cross-process macOS event posting/TCC prompts avoided for native keyboard automation; provider traversal remains explicitly distinct from external screen-reader speech.

Sources: [Tauri WebDriver](https://tauri.app/develop/tests/webdriver/), [Tauri CI](https://tauri.app/develop/tests/webdriver/ci/), [NSEvent constructor](https://developer.apple.com/documentation/appkit/nsevent/keyevent%28with%3Alocation%3Amodifierflags%3Atimestamp%3Awindownumber%3Acontext%3Acharacters%3Acharactersignoringmodifiers%3Aisarepeat%3Akeycode%3A%29), [WKPreferences keyboard focus](https://developer.apple.com/documentation/webkit/wkpreferences/tabfocuseslinks), [DBus session lifetime](https://dbus.freedesktop.org/doc/dbus-run-session.1.html). Installed plugin1.5.0 executor/platform code was inspected. Mechanisms still require actual elected runtime execution.

## 2026-10-27: Media observations

Decision: separate synthetic corpus, known quadrants/alpha, seven representative formats, all eight EXIF orientations, tagged/untagged SDR color, H264/AAC and VP9/Opus moving clips, 440Hz tone plus silent control. Existing clip audio is anullsrc; muted=false does not qualify decoded audio. Use actual media element WebAudio analyser samples with explicit graph/output limits. Existing anonymous media and strict reflected origin already permit canvas/audio access; no wildcard change.

Alternatives: broad codec promises, extension/canPlayType hints, first-frame-only playback and animation inferred from canvas rejected. Canvas uses current video frames but default/first animated-image frame by specification. Known unsupported media remains inspectable and is recorded per runtime.

Sources: [canvas sources](https://html.spec.whatwg.org/multipage/canvas.html#image-sources-for-2d-rendering-contexts), [canvas color conversion](https://html.spec.whatwg.org/multipage/canvas.html#color-spaces-and-color-space-conversion), [WebAudio media sources](https://www.w3.org/TR/webaudio-1.0/#MediaElementAudioSourceNode), [Pillow ImageCms](https://pillow.readthedocs.io/en/latest/reference/ImageCms.html), [FFmpeg sine](https://ffmpeg.org/ffmpeg-filters.html#sine), [WebKitGTK multimedia](https://docs.webkit.org/Ports/WebKitGTK%20and%20WPE%20WebKit/Multimedia.html).

### Remote input and accessibility setup correction

The Windows hosted run exposed actual NVDA speech/focus for Refresh but no subsequent Tab delivery through the legacy SendKeys path. Retain NVDA's normal injected-key handling and use documented Win32 SendInput scan-code pairs for the new campaign, still requiring foreground confirmation and actual native default behavior. Compile and verify native INPUT layout headlessly; execute keys only on isolated CI. Sources: [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput), [INPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-input), [elected NVDA keyboard handler](https://github.com/nvaccess/nvda/blob/release-2026.3/source/keyboardHandler.py).

The Linux status setup used the wrong object path. GNOME registers org.a11y.Status at /org/a11y/bus, alongside the bus interface. Correct that path rather than treating an unavailable provider as a codec result. Source: [AT-SPI bus launcher](https://github.com/GNOME/at-spi2-core/blob/main/bus/at-spi-bus-launcher.c).

Mac's native WebM media-element audio observer differs from native buffer decoding. Actual isolated comparison probes show successful ordinary playback and native decoded tone PCM but an unavailable media-element PCM tap. [WebKit issue276813](https://bugs.webkit.org/show_bug.cgi?id=276813) describes the separate WebM media-element/WebAudio path and incorrect gain behavior; it supports investigating that boundary, not inferring current qualification from a bug report. Retain actual source-bound video observations and independently identified native buffer PCM evidence, with the media-element output limitation explicit.

The initial AppKit walk stopped at a remote AX child. The actual class is NSAccessibilityRemoteUIElement, an Objective-C provider proxy, not a bridged AXUIElement. WebKitTestRunner obtains WKWebView's _remoteAccessibilityChildToken and calls _AXUIElementCreateWithRemoteToken before querying ApplicationServices AX attributes. The test-only bridge checks that newer selector, falling back to AppKit's remoteTokenForLocalUIElement for the actual WKWebView. Query the native client off the main thread so AppKit can service callbacks, request its enhanced accessible interface, and await actual named controls. Preserve proper CF ownership, 0.1-second message bounds, a five-second traversal deadline, bounded depth/nodes and recorded errors. Missing tokens, symbols or control exposure cannot pass. This SPI is excluded from ordinary product artifacts and can require adaptation with another WebKit release. Sources: [WebKit native AX client](https://github.com/WebKit/WebKit/blob/main/Tools/WebKitTestRunner/TestController.cpp), [Mac test-runner bridge](https://github.com/WebKit/WebKit/blob/main/Tools/WebKitTestRunner/mac/TestControllerMac.mm), [AppKit remote-provider SPI](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/PAL/pal/spi/cocoa/NSAccessibilitySPI.h). No DOM label fallback or external VoiceOver speech claim is introduced.

The Mac WebM player also rejects canvas frame read-back despite correct delivery headers. [WebKit CORS implementation](https://github.com/WebKit/WebKit/commit/81d69724b4b62e74af261ba14614f097e97c34cd) describes that engine boundary. Use actual native-view snapshots for this elected video, with an independently decoded central media crop excluding controls, nonblank colored-pattern checks, changing frame hashes and an independently changed sought frame. Keep exact screenshots/hashes and actual playback/seek/range observations. Do not disable CORS or substitute a separately decoded video for the visible player.

The ordinary rebuilt distinct-consumer URL did not solve startup, so remove it rather than preserve an ineffective workaround. Installed ReactDOM setInitialProperties defers image src but applies video properties in their declared order. The existing video JSX assigned src before anonymous CORS and metadata-only preload; explicit post-mount reload used by the diagnostic instead starts after those properties exist. Configure CORS/preload before src in both card and focused video elements. A bounded native setAttribute observer records their actual values at source assignment and fails any improperly initialized video. No transport authority or source URL changes are necessary.
